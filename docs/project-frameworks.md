# 프로젝트 프레임워크 정리

## 문서 기준 기술 스택

이 프로젝트는 모바일 중심 내부 업무관리 앱으로 기획되어 있으며, 아래 조합이 가장 잘 맞습니다.

### 1. Next.js + React

- 역할: 프론트엔드 웹앱 프레임워크
- 이유: App Router, React 컴포넌트 구조, 배포 호환성이 좋아 빠르게 화면을 만들 수 있습니다.
- 적용 영역: 로그인, 업무 목록, 상세 화면, 관리자 화면

### 2. TypeScript

- 역할: 타입 안정성 확보
- 이유: 직위, 업무 상태, 피드백, 첨부파일 같은 데이터 구조가 많아서 초기에 타입을 잡아두는 것이 중요합니다.
- 적용 영역: 도메인 모델, 폼 데이터, API 응답, 컴포넌트 props

### 3. Tailwind CSS

- 역할: UI 스타일링
- 이유: 모바일 우선 레이아웃과 빠른 시안 반영에 적합합니다.
- 적용 영역: 카드, 배지, 폼, 버튼, 화면 간격 시스템

### 4. shadcn/ui

- 역할: 공통 컴포넌트 시스템
- 이유: 로그인 폼, 시트, 다이얼로그, 탭, 카드, 테이블을 일관성 있게 조합할 수 있습니다.
- 적용 영역: 입력 폼, 상태 배지, 관리자 액션 버튼, 하단 시트

### 5. NestJS Backend API

- 역할: 프론트엔드와 분리된 업무 도메인 API 서버
- 이유: 인증, 권한, PostgreSQL 접근, 파일 업로드 같은 서버 책임을 프론트엔드와 분리할 수 있습니다.

구성 요소:

- 로그인/인증 API
- `PostgreSQL`: 사용자, 업무, 피드백, 상태 변경 기록 저장
- 권한 미들웨어: 대표/관리자/직원 접근 제어
- 파일 업로드 API: 사진, 결과물 이미지 업로드
- 알림 API: 진행상황과 피드백 이벤트 저장/조회

### 6. PWA

- 역할: 모바일 앱처럼 사용하는 웹앱 구성
- 이유: 홈 화면 추가와 모바일 사용성을 강화할 수 있습니다.
- 적용 영역: 설치 가능 웹앱, 아이콘, 오프라인 기본 대응

### 7. 배포

- 역할: 프론트엔드와 백엔드 배포
- 이유: 프론트엔드는 Next.js 배포에 적합한 플랫폼을 사용하고, 백엔드는 PostgreSQL 연결이 안정적인 서버 환경에 배포합니다.

### 8. lucide-react

- 역할: 아이콘 시스템
- 이유: 체크, 카메라, 알림, 뒤로가기, 사용자, 목록 아이콘을 가볍게 구성할 수 있습니다.

## 이 프로젝트에 특히 잘 맞는 이유

- 모바일 우선 화면을 빠르게 만들 수 있습니다.
- 역할 기반 접근 제어가 중요해 백엔드 권한 미들웨어에서 명확히 관리해야 합니다.
- 사진 업로드, 상태 변경, 피드백 기록 같은 기능을 API 중심으로 분리해 관리할 수 있습니다.
- 초기 MVP부터 운영 단계까지 확장 경로가 자연스럽습니다.

## 디자인 반영 메모

- 파스텔 톤 기반 모바일 UI
- 둥근 카드, 배지, 버튼 중심
- 핑크/크림/라벤더 계열 메인 색상
- 마스코트 또는 일러스트를 보조적으로 활용
